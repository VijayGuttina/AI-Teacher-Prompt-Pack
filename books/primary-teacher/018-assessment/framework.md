# 018 Assessment Framework

## Purpose

This framework defines the architecture, quality standards and verification approach for the Primary Teacher Prompt Pack: Assessment.

The module is designed to help primary teachers plan assessment, check understanding, gather valid evidence, give useful feedback, diagnose misconceptions, evaluate progress, plan proportionate intervention and moderate judgements.

Assessment prompts must support professional judgement rather than replace it. They should help teachers assess the intended learning construct, not reward superficial recall, compliance, speed, confidence or familiarity with assessment language.

## Core Principles

1. **Purpose before method**: define why the assessment is being conducted before selecting a task, question or assessment format.
2. **Construct validity**: assess the intended knowledge, skill, reasoning or application rather than incidental barriers.
3. **Evidence before judgement**: make judgements from sufficient relevant evidence, not isolated performance.
4. **Assessment informs teaching**: formative assessment should lead to a meaningful instructional response where appropriate.
5. **Assessment is not teaching by another name**: do not turn every lesson into a formal test.
6. **Proportionate assessment**: assessment should justify its time, workload and pupil burden.
7. **Progress over time**: progress should be interpreted against prior learning, curriculum expectations and meaningful evidence.
8. **Misconceptions require diagnosis**: an incorrect answer is evidence to investigate, not automatically proof of a specific misconception.
9. **Feedback should improve learning**: feedback should be actionable, timely enough to matter and proportionate to the task.
10. **Do not reward compliance**: neatness, speed, silence, confidence or behaviour should not be treated as attainment evidence unless they are genuinely part of the intended construct.
11. **Equity is not identical treatment**: reasonable access adaptations may be required to allow pupils to demonstrate the intended learning.
12. **SEND and EAL access must preserve the construct**: remove incidental barriers without automatically lowering the learning demand.
13. **Teacher workload matters**: avoid unnecessary marking, data collection and assessment bureaucracy.
14. **Pupil dignity matters**: assessment should not unnecessarily expose, embarrass or label pupils.
15. **Transparency**: where a judgement is uncertain, state the evidence gap rather than inventing precision.
16. **Moderation improves consistency**: professional dialogue and shared exemplification should support reliable judgements.
17. **Current requirements require verification**: statutory assessment, reporting or school-specific policy claims must be checked against current authoritative guidance.
18. **Teacher judgement remains central**: generated assessment materials are decision-support tools, not autonomous grading systems.

## Standard Assessment Cycle

Use where appropriate:

**Intent → Assessment purpose → Construct → Evidence → Task/check → Elicit → Interpret → Respond → Reassess → Record only what is useful**

The cycle should not require every stage for every classroom assessment. Prompts should select only the stages necessary for the teacher's purpose.

## Assessment Construct Model

Before generating an assessment, prompts should identify:

- curriculum objective
- intended knowledge or skill
- level of thinking required
- prerequisite knowledge
- application or transfer requirement
- acceptable evidence of success
- common errors or misconceptions
- incidental barriers
- accessibility requirements
- whether the assessment is formative or summative

The output should make clear what is being assessed and what is deliberately **not** being assessed.

## Formative Assessment Model

Formative assessment should support:

**Elicit → Interpret → Decide → Adapt teaching → Check impact**

Possible evidence sources include:

- targeted questions
- hinge questions
- mini-whiteboards
- retrieval checks
- worked examples
- pupil explanations
- guided practice
- independent work
- exit tickets
- observation of application
- short quizzes
- practical demonstrations

A formative check should not be included merely because it looks like assessment. The prompt should explain what decision the evidence will support.

## Retrieval and Knowledge Assessment

Retrieval workflows should distinguish:

- recognition
- recall
- accurate recall
- fluent recall
- connected knowledge
- application
- transfer

Retrieval should be cumulative where appropriate and should revisit important prior learning. Do not treat repeated exposure as proof of secure learning.

## Misconception and Error Analysis Model

Use:

**Response → Error pattern → Possible explanation → Evidence needed → Diagnostic check → Teaching response → Recheck**

Do not claim that one incorrect answer proves a particular misconception.

Distinguish among:

- conceptual misunderstanding
- procedural error
- calculation or transcription error
- vocabulary/language barrier
- reading demand
- memory failure
- attention/task-management issue
- unfamiliar representation
- incomplete prior knowledge
- ambiguity in the task

## Feedback Model

Effective feedback should answer:

1. Where am I now?
2. Where am I trying to get to?
3. What is the next useful action?

Feedback should be:

- specific
- actionable
- proportionate
- linked to the learning objective
- understandable to the pupil
- feasible to act on
- followed by an opportunity to improve where appropriate

Do not generate large volumes of low-value written marking merely because a task exists.

## Summative Assessment Model

Summative workflows should distinguish:

- evidence collection
- scoring or marking
- interpretation
- professional judgement
- confidence/uncertainty
- reporting

Where a numerical score is generated, prompts should explain what the score can and cannot support. Avoid false precision.

## Progress and Intervention Model

Progress should use comparable and meaningful evidence over time. Prompts should avoid simplistic percentage-growth claims where the underlying measures are not comparable.

Intervention should follow:

**Identified gap → Baseline → Target → Strategy → Practice → Review → Evidence → Decision**

Possible decisions include:

- continue
- adapt
- intensify
- generalise
- fade
- exit
- seek additional professional input

Do not claim intervention causality without appropriate evidence.

## Moderation and Reliability

Moderation workflows should support:

- shared criteria
- common standards
- exemplification
- independent initial judgement where useful
- professional discussion
- identification of borderline cases
- documentation of rationale
- resolution of disagreement
- calibration over time

Do not force agreement where evidence genuinely supports more than one reasonable interpretation. Record the rationale and uncertainty.

## Inclusion, SEND and EAL Assessment

Assessment adaptations may include:

- accessible layout
- enlarged or clearer presentation
- additional processing time where appropriate
- oral rehearsal where it does not change the construct
- alternative response mode
- reduced incidental reading load
- visual supports
- assistive technology where supplied and appropriate
- chunking or staged presentation

The prompt must identify whether an adaptation changes the construct. For example, reducing handwriting demand may preserve a subject-content construct, while translating a language-dependent reading assessment may alter the construct.

Do not infer SEND, EAL, disability or ability from assessment performance alone.

## Assessment Leadership and Workload

Leadership workflows should consider:

- assessment intent
- consistency
- curriculum alignment
- teacher workload
- data quality
- usefulness of collected data
- pupil workload
- reporting requirements
- moderation
- intervention linkage
- assessment calendar design
- staff training
- quality assurance

Avoid creating assessment systems that generate large amounts of data without a clear decision or action attached.

## Assessment Language Standards

Prefer:

- "evidence suggests"
- "the response indicates"
- "this may indicate"
- "check whether"
- "possible explanation"
- "confidence is limited because"
- "requires further evidence"

Avoid unsupported statements such as:

- "the pupil cannot"
- "the pupil is weak at"
- "this proves"
- "the pupil has a misconception" based on one response
- "the pupil is below ability"
- "the intervention caused progress" without evidence

Use strengths-aware, precise language.

## Missing Information Protocol

When essential information is missing:

1. Identify what is missing.
2. Explain why it affects the assessment decision.
3. Use a clearly labelled assumption only where safe.
4. Provide a usable generic structure where possible.
5. State what the teacher should verify before relying on the output.

Never invent:

- statutory assessment requirements
- school assessment policy
- marking schemes not supplied
- standardised test norms
- pupil data
- previous attainment
- SEND/EAL status
- moderation decisions
- safeguarding procedures
- current national assessment arrangements

## Quality Gates

Every Assessment workflow must pass:

### Purpose
- Assessment purpose is explicit.
- The output identifies the decision the evidence will support.

### Construct
- Intended learning construct is explicit.
- Incidental barriers are separated from essential demands.
- Accessibility adaptations do not silently change the construct.

### Evidence
- Evidence is relevant and sufficient for the judgement claimed.
- Uncertainty is acknowledged.
- Multiple evidence sources are used where appropriate.

### Teaching response
- Formative assessment leads to a plausible next teaching action.
- Misconception claims are evidence-led.
- Intervention decisions include review points.

### Feedback
- Feedback is actionable and linked to the learning objective.
- Workload is proportionate.
- Pupils have an opportunity to act on feedback where appropriate.

### Inclusion
- SEND and EAL adaptations preserve intended learning where possible.
- No diagnosis is inferred.
- Pupil dignity and privacy are protected.

### Reliability
- Moderation and judgement criteria are explicit where relevant.
- False precision is avoided.

### Current requirements
- Current statutory or policy claims are flagged for authoritative verification.
- School-specific requirements are treated as variables unless supplied.

## Verification Model

The Assessment module will follow the established 100-workflow release discipline:

1. **Framework integrity**: exactly 10 families × 10 workflows = 100 workflows.
2. **Structural QA**: 100/100 workflows complete against the master specification.
3. **Representative execution testing**: exactly 20 workflows, two per family.
4. **Targeted risk checks**: exactly 16 assessment-specific checks.
5. **Verification record and freeze** only after all required stages pass.

Structural completeness does not constitute execution verification.

## Targeted Risk Checks

1. Construct validity and assessment purpose
2. Avoidance of false precision and unsupported grading claims
3. Formative assessment leading to meaningful teaching decisions
4. Misconception diagnosis based on evidence rather than single errors
5. Accurate distinction between knowledge, skill, application and transfer
6. Feedback that is actionable and proportionate
7. Avoidance of unnecessary marking and workload
8. Progress judgements based on meaningful comparable evidence
9. Intervention design with baseline, outcome and review logic
10. Moderation and reliability without forced agreement
11. SEND assessment access without construct distortion
12. EAL and language access without conflating English proficiency with subject knowledge
13. Pupil dignity, privacy and avoidance of unnecessary labelling
14. Safe handling of missing pupil, school and assessment-policy information
15. Current statutory assessment and reporting claims requiring authoritative verification
16. Appropriate use of generated assessment materials without replacing teacher judgement

## Definition of Done

The Assessment module is complete only when:

- the framework defines exactly 10 families and 100 workflows
- all 100 workflows follow the agreed prompt architecture
- required metadata and examples are present
- assessment purpose and construct validity are embedded
- formative assessment and responsive teaching are addressed
- retrieval and knowledge assessment are addressed
- misconception and error analysis are evidence-led
- feedback and marking are actionable and proportionate
- summative assessment and judgement are appropriately bounded
- progress and intervention are evidence-led
- moderation and reliability are addressed
- SEND and EAL assessment access is construct-valid
- assessment leadership and workload controls are addressed
- missing-information handling is explicit
- structural QA passes 100/100
- representative execution testing passes 20/20
- targeted risk checks pass 16/16
- verification and freeze records are completed
- the module is explicitly marked frozen only after all verification stages pass
