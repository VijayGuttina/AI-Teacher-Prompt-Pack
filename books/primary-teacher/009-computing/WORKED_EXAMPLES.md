# Computing Worked Examples

These examples demonstrate how the workflows should be used. They are illustrative examples, not execution-verification evidence.

## Example 1 — Debugging pupil code

**Workflow:** PT-04  
**Input:** A Year 5 pupil's Scratch-style pseudocode repeats a movement instruction but never reaches the stated end condition.  
**Expected approach:** Identify the missing or ineffective stopping condition, explain why the loop does not terminate as intended, propose the smallest conceptual fix, and provide test cases. Do not claim the code was executed.

## Example 2 — Data interpretation

**Workflow:** DI-05  
**Input:** A supplied table shows weekly counts of recyclable items collected by four classes.  
**Expected approach:** Identify only patterns supported by the table, distinguish description from causal explanation, and quote the supplied values accurately.

## Example 3 — Online safety

**Workflow:** OS-03  
**Input:** A fictional message asks a pupil to click a link and enter account details urgently.  
**Expected approach:** Identify urgency, request for credentials and suspicious-link indicators; advise not to interact with the message and to use the appropriate trusted-adult/reporting route. Never request or reproduce real credentials.

## Example 4 — Algorithm diagnosis

**Workflow:** AD-08  
**Input:** A pupil's algorithm contains correct instructions but places the decision after an action that should only occur when the condition is true.  
**Expected approach:** Use the supplied evidence to diagnose a selection/sequence misunderstanding, ask a discriminating trace question, then reteach the relationship between condition and action.

## Example 5 — Adaptive programming task

**Workflow:** PT-10  
**Input:** A Year 4 task asks pupils to create a program using sequence and repetition. A learner needs support with reading code but can reason verbally about repeated actions.  
**Expected approach:** Provide visual or partially completed code scaffolds while retaining the need to identify repetition and predict behaviour. Include an independence route that removes the scaffold progressively.

## Example 6 — Assessment-to-action

**Workflow:** CA-10  
**Input:** Exit-ticket evidence shows that most pupils can identify a loop but several cannot explain when a loop should stop.  
**Expected approach:** Convert the evidence into a focused diagnosis, a short reteach using trace examples, a discriminating check, and a transfer task. Do not infer causes that the evidence does not support.
