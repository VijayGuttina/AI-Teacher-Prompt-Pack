# Computing Assessment, Diagnosis & Intervention Workflows

**IDs:** CA-01 to CA-10

## CA-01 — Create an Objective-Aligned Assessment
**ROLE:** Primary computing teacher. **CONTEXT:** Objective, year group and taught content supplied. **TASK:** Create a short assessment. **REQUIREMENTS:** Assess the stated Computing construct, not merely recall unless recall is the objective. **OUTPUT FORMAT:** Questions, answers, mark guidance, misconception map. **QUALITY CHECKS:** Alignment and technical accuracy. **OPTIONAL CUSTOMISATION:** Duration.

## CA-02 — Create an Exit Ticket
**ROLE:** Computing teacher. **CONTEXT:** Lesson objective supplied. **TASK:** Create an exit ticket that reveals understanding. **REQUIREMENTS:** Include at least one discriminating item. **OUTPUT FORMAT:** 3-5 questions, answers, response actions. **QUALITY CHECKS:** Diagnostic value. **OPTIONAL CUSTOMISATION:** Year group.

## CA-03 — Create a Hinge Question
**ROLE:** Diagnostic computing teacher. **CONTEXT:** Concept and likely misconceptions supplied. **TASK:** Create a whole-class hinge question. **REQUIREMENTS:** Each option should correspond to a plausible conceptual position. **OUTPUT FORMAT:** Question, options, misconception map, teacher response. **QUALITY CHECKS:** Diagnostic power. **OPTIONAL CUSTOMISATION:** Oral/mini-whiteboard.

## CA-04 — Analyse Pupil Computing Work
**ROLE:** Computing assessment specialist. **CONTEXT:** Pupil work, code, algorithm or explanation supplied. **TASK:** Identify strengths, errors and likely misconceptions. **REQUIREMENTS:** Separate observed evidence from inference. **OUTPUT FORMAT:** Evidence, diagnosis, priority gap, next check. **QUALITY CHECKS:** No unsupported diagnosis. **OPTIONAL CUSTOMISATION:** Individual/class.

## CA-05 — Group Learners for Targeted Teaching
**ROLE:** Computing teacher. **CONTEXT:** Assessment evidence supplied. **TASK:** Propose flexible groups by identified need. **REQUIREMENTS:** Use evidence-based grouping and avoid fixed labels. **OUTPUT FORMAT:** Group rationale, objective, task, exit check. **QUALITY CHECKS:** Evidence alignment. **OPTIONAL CUSTOMISATION:** Class size.

## CA-06 — Design a Targeted Intervention
**ROLE:** Computing intervention teacher. **CONTEXT:** Specific misconception/skill gap supplied. **TASK:** Design a short intervention. **REQUIREMENTS:** Preserve the Computing construct and include a discriminating check. **OUTPUT FORMAT:** Diagnosis, explanation, guided practice, independent check, next decision. **QUALITY CHECKS:** Construct alignment. **OPTIONAL CUSTOMISATION:** 10/20 minutes.

## CA-07 — Create Adaptive Computing Tasks
**ROLE:** Inclusive computing teacher. **CONTEXT:** Objective, original task and learner evidence supplied. **TASK:** Create accessible variants without reducing computational demand unnecessarily. **REQUIREMENTS:** State what is scaffolded and what remains constant. **OUTPUT FORMAT:** Core task, scaffold, support, stretch, success criteria. **QUALITY CHECKS:** Construct preservation. **OPTIONAL CUSTOMISATION:** SEND/EAL.

## CA-08 — Plan Retrieval and Re-teach
**ROLE:** Primary computing teacher. **CONTEXT:** Assessment gaps supplied. **TASK:** Build a retrieval-to-reteach cycle. **REQUIREMENTS:** Start from diagnosed gaps and finish with transfer. **OUTPUT FORMAT:** Retrieval, reteach, guided practice, transfer check. **QUALITY CHECKS:** Alignment. **OPTIONAL CUSTOMISATION:** Lesson length.

## CA-09 — Summarise Assessment Evidence
**ROLE:** Computing assessment lead. **CONTEXT:** Assessment data and observations supplied. **TASK:** Produce an evidence-based summary. **REQUIREMENTS:** Do not infer causes beyond the evidence. **OUTPUT FORMAT:** Strengths, gaps, patterns, confidence/limitations, recommended actions. **QUALITY CHECKS:** Evidence fidelity. **OPTIONAL CUSTOMISATION:** Pupil/class/team audience.

## CA-10 — Build an Assessment-to-Action Cycle
**ROLE:** Primary computing teacher. **CONTEXT:** Objective and evidence supplied. **TASK:** Convert assessment evidence into a teaching decision cycle. **REQUIREMENTS:** Link evidence to diagnosis, intervention and re-check. **OUTPUT FORMAT:** Evidence → diagnosis → action → check → next decision. **QUALITY CHECKS:** Traceability and construct alignment. **OPTIONAL CUSTOMISATION:** Individual/small group/class.
