## Purpose

This register separates repository-level structural quality assurance from actual execution testing. A workflow is not labelled **Verified** merely because it was authored with or reviewed by an AI model.

## Status definitions

| Status | Meaning |
|---|---|
| Not Yet Tested | No representative execution has been reviewed. |
| Structural QA Pass | Workflow structure and subject safeguards have been checked. |
| Tested - Fix Required | Execution exposed an issue requiring revision. |
| Verified | Representative execution passed the agreed quality checks and reviewer notes have been recorded. |
| Re-verify | Previously verified workflow requires review after a material workflow, model or policy change. |

## Verification fields

Each execution test should record:

- Workflow ID
- Workflow file
- AI tool
- Exact model/model family where available
- Test date
- Representative input
- Output result
- Reviewer notes
- Defects or risks identified
- Corrective action
- Final status
- Next review date

## Subject-specific verification checks

Every executed workflow should be checked for:

1. **Artistic agency** — AI must not unnecessarily determine the pupil's artistic outcome.
2. **Construct validity** — assessment must target the intended artistic learning rather than neatness, speed or conformity.
3. **Evidence discipline** — observations, interpretations and hypotheses must remain distinguishable.
4. **Cultural accuracy** — historical and cultural claims must not be invented, flattened or presented with unjustified certainty.
5. **Technical accuracy** — material, process and tool claims must be plausible and appropriately qualified.
6. **Inclusion** — adaptations should remove barriers without automatically lowering intellectual or artistic demand.
7. **Practicality** — outputs must be usable in a normal primary classroom.
8. **Age appropriateness** — vocabulary, task demands and safeguarding boundaries must match the stated age group.
9. **Cross-curricular validity** — where another subject is involved, evidence for each discipline must remain clear.
10. **Safety and permissions** — practical materials, digital media, images and public display must include relevant safeguards.

## Verification policy

Execution verification should use representative, realistic teacher inputs rather than artificial one-line tests. High-risk workflows, particularly cultural-context, assessment, inclusion, digital-image and subject-leadership workflows, should receive targeted scrutiny.

Verification does not constitute a guarantee of output accuracy. Teachers remain responsible for professional judgement, checking factual claims, safeguarding, school policy and suitability for their pupils.

## Review cadence

Verified workflows should be reviewed after a material model change, material workflow revision, significant policy change, or at the next scheduled quarterly review. A dated review schedule should be recorded once execution verification begins.
