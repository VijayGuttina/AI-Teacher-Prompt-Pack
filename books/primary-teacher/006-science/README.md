# Primary Science Workflow Library

Science is organised by teacher job-to-be-done rather than a flat list of prompts.

## Architecture

```text
Global Prompt Standard
        ↓
Master Prompt Framework
        ↓
Primary Teacher Framework
        ↓
Science Framework
        ↓
Science Workflow
        ↓
AI Output
```

## Initial workflow coverage

| Strand | Initial target |
|---|---:|
| Working scientifically | 10 |
| Living things, plants, animals and humans | 10 |
| Materials and changes | 10 |
| Forces and motion | 10 |
| Light, sound, electricity and energy | 10 |
| Earth, space and environmental science | 10 |
| Classification, habitats and adaptation | 10 |
| Assessment, diagnosis and intervention | 10 |
| **Initial library target** | **80** |

The target is a planning ceiling, not a requirement to manufacture workflows. A workflow should only be added when it represents a materially different teacher job-to-be-done.

## Quality standard

Every workflow inherits the Science Framework and must include appropriate factual, enquiry and age-appropriateness checks. Generated explanations, practical procedures, data, diagrams, questions and answer keys must be checked before publication.

## Verification standard

Each published workflow will receive verification metadata recording:

- AI tool
- Exact model / model family
- Test date
- Representative test input
- Verification result
- Reviewer notes
- Next scheduled review

Newly authored workflows remain `Not Yet Tested` until representative execution has actually been performed.

## Commercial design principle

The Science book should function as a practical professional reference tool. It should not become a wall of repetitive prompts simply to increase the advertised count.
